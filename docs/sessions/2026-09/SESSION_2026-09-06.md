## 🎯 Objectif
Système de réservation par créneaux : le client choisit son créneau AVANT le paiement,
la coach gère tout depuis son mobile, synchronisation avec Google Calendar.

## ✅ Accomplissements (5 phases committées sur feature/booking)

### Phase 1 — Données & logique créneaux (0e75453)
- `Service.durationMinutes` (durée numérique pour découper les créneaux)
- `Reservation` : `startAt`, `endAt`, `holdExpiresAt`, statut `en_attente`, index startAt
- Modèles `AvailabilityRule` (horaires hebdo + buffer) et `Unavailability` (blocages)
- `src/lib/slots.ts` : moteur de calcul (UTC, DST Paris via Intl, buffers, indispos, verrous) + horaires par défaut (lun-ven 8-20, sam 9-18)
- API `GET /api/slots?serviceId=&date=`
- Champ optionnel "Informations santé / besoins" réintroduit dans le formulaire

### Phase 2 — Sélecteur + soft-lock (a030f68)
- `SlotLock` (verrou 15 min, libération paresseuse sans cron)
- `src/lib/booking.ts` : isSlotFree / createSlotLock / releaseSlotLock
- Composant `SlotPicker` intégré au formulaire (les 2 modes de paiement)
- Validation serveur à la finalisation (409 si créneau pris entre-temps)
- Créneau passé aux metadata Stripe

### Phase 3 — Webhooks robustes + emails + .ics (ecb7487)
- Idempotence ATOMIQUE (updateMany conditionnel) — anti double envoi d'emails
- Vérification montant (DB vs Stripe)
- `checkout.session.expired` + `charge.refunded` → annulation + libération du créneau + email
- `async_payment_failed` / `payment_intent.payment_failed` → email "Paiement non abouti"
- Retour 500 sur erreur réelle (Stripe retry), 200 idempotent
- Emails : date+heure du créneau (Paris), 2 nouveaux templates (échec, remboursement)
- **Fichier .ics** joint aux emails client (compatible Apple/Google/Outlook)

### Phase 4 — Admin mobile-first (de71404)
- Onglet "Réservations" : agenda du jour (7 jours), réservations avec appel `tel:` + annulation
- Blocage 1 tap : Matin / Après-midi / Journée
- Horaires hebdomadaires éditables (dimanche fermé par défaut)
- 5 server actions protégées requireAdmin + audit trail

### Phase 5 — Google Calendar OAuth2 (0175544)
- `src/lib/google-calendar.ts` : OAuth2 mono-compte, tokens chiffrés AES-256-GCM
- Sync descendante : indispos Google → blocages (source: 'google')
- Sync montante : réservation payée → événement agenda (supprimé si annulation/remboursement)
- Routes admin protégées : /auth (redirect OAuth), /callback, POST sync/disconnect/status
- Section "Google Calendar" dans l'admin (connecter / synchroniser / déconnecter)
- Intégration inactive si non configurée (no-op partout)
